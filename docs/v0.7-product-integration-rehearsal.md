## Remediation note (2026-09-30)

`fe123ef` was functionally green, but its Local Data lineage was wrong. Merge
`4ad225e` adopted `codex/v0.7-local-data-controls` @ `2f34ae4`; that branch was
later superseded by the reconciled `feature/v0.7-local-data-controls` @
`b6ecdfc`. This remediation starts at `fe123ef`, removes the superseded
contract from the product surface, and ports the accepted product integration
fixes onto the canonical Local Data semantics without replaying `2f34ae4`.

The integrated execution-runs product store remains
`limitscope.execution-runs.v1` so the accepted run affordance and receipt
pipeline are unchanged. Its clear behavior now follows the canonical
execution-data contract: completed runs clear normally, while an active run is
removed only by the explicit "Discard active run and clear" confirmation.

Expected semantic differences from `fe123ef`:

- branch ancestry and documentation now name `b6ecdfc` as canonical;
- the Local Data catalog and component use `localDataControls(activeExecutionRun)`;
- provider-cache clear removes persisted recovery data and its interrupted
  `.json.tmp` write without rewriting the current in-session runtime snapshot;
- execution clear has a store-level active-run confirmation guard;
- regression pins cover the provider-cache contract, six-field settings,
  unknown-field retention, and execution clear boundaries;
- `scripts/css-rule-safe-merge.mjs` and `src/cssSyntax.test.ts` guard complete
  CSS blocks and recurrence of the earlier splice failure.

Provider-cache contract: `clear_provider_cache` clears only the persisted
last-good recovery cache. The currently visible runtime snapshot remains until
the next normal refresh replaces it, and a reopened/cold-start store hydrates
nothing from the cleared cache.

CLI provenance boundary: `.limitscope-provenance-run.json` remains owned by
`scripts/provenance.mjs` where that CLI runs. The desktop app never scans the
process CWD or workspaces for it and has no generic `delete(path)` or provider
credential mutation surface.

CSS safe-merge rule: final CSS changes must merge complete parsed blocks by
selector. Text splicing is prohibited. The final stylesheet was rebuilt via
the rule-safe merge from canonical Local Data blocks (11 replacements, zero
appended blocks), remained byte-identical to the accepted repaired sheet, and
passed brace/comment/string syntax checks plus real-browser visual smoke.

## 4. Semantic resolutions (accepted contracts, unchanged)

- **Quota perspective**: `Used | Remaining`; default `Used`;
  `quotaPresentation.ts` remains the single inversion boundary;
  `usedPercent` stays the sole canonical value in backend, history,
  severity, thresholds, and predictions. 95% used reads
  "Critical · 5% remaining".
- **Usage UI × perspective**: summary values and the most-constrained metric
  show the complement in Remaining mode; exactness badges flip to the honest
  "upper bound"; trend summaries name the lowest remaining point while the
  plot, axis, and 80% guide stay canonical; heatmap cell labels show the
  complement while the band class still tracks used ("16% remaining (84%
  used), band 75–100%"); near-limit stays `≥80% used` / `≥95% used` with an
  explicit equivalence note ("thresholds measure used: ≤20% remaining ≈
  ≥80% used"). No backend analytics inverted anywhere.
- **Heatmap**: fixed absolute used bands (0/25/50/75/100); colors never
  reversed; unobserved days stay hatched/dashed, never zero-filled.
- **Execution runs**: run controls stay in the header on both views (no move
  into Usage, no deep integration); receipts deterministic
  (`formatReceiptJson` byte-identical across runs; reset-crossing runs pin
  `reset-crossed` windows and never export negative deltas).
- **Codex reset credits**: `bankedCredits` / `currentlyApplicable` stay
  banked-balance observations; never inverted in Remaining mode; never
  entered into Usage history; coexist with `planType` on `ProviderUsage`.
- **Local data**: Usage history / Provider cache / Execution runs /
  Preferences — exactly one section, each with in-place confirmation naming
  what is removed and preserved; active execution runs require the explicit
  discard confirmation; account isolation and credential boundaries come from
  canonical `b6ecdfc`; no "delete everything" control.
- **Settings**: canonical object is `launchAtStartup`,
  `refreshIntervalMinutes`, `theme`, `quotaNotifications`,
  `providerPreferences`, `quotaPerspective` under
  `rate-limits.settings.v1`; saves merge through `mergeSettingsWithRaw`, so
  unknown/foreign fields survive saves and resets; reset restores
  `quotaPerspective: "used"` and canonical defaults.

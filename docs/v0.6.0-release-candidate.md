## 5. Core runtime and provider contracts

- Rust-owned canonical `ProviderHealth`: `live`, `stale`, `unknown`,
  `cooldown`, `error`, `unavailable`, single write point `set_health()`;
  legacy `status` is the derived projection. Pinned by the
  runtime-status-contract tests inside the 367-test Rust suite.
- History and notifications accept only canonical live/fresh observations
  (`history::eligibility_accepts_only_live_canonical_health`); persisted
  last-good hydrates as `stale`, never live, never notifies.
- Provider account change never retains another account's last-good
  (`opencode_last_good_is_dropped_when_the_stored_account_changed`).
- History: 24h detailed tier + 7d bounded compacted tier, reset boundaries
  preserved across compaction, prediction queries isolated to dense-24h,
  hard retention caps, no smoothing through resets.
- Notifications: near-limit/critical crossing-only, reset-cycle re-arm,
  per-account isolation, stale/error/cooldown/unavailable suppression,
  shared burst cap, recovery only on genuine forward reset progression with
  a proven previous peak.
- Production providers (five): openai-codex, zai, opencode-go,
  antigravity, grok. Codex reads only its own auth source; Z.ai attribution
  follows the actual credential attempted; a single OpenCode auth.json key
  is credential truth; Antigravity uses live Google quota with plugin-cache
  fallback; Grok uses the weekly billing source. No browser-cookie
  scraping; OpenCodex private credentials are never a production source.
- Identity vocabulary (unified, from identity-hardening): Codex masked
  account (`account ••ff69dd62`), Z.ai masked attempted key (`key ••48RE`),
  OpenCode Go key tail (`key ••avmF`), Antigravity plugin cache (accepted
  weak attribution), Grok strong masked id (`xai:7a2d5abe…`). No alternate
  vocabulary was introduced.

## 6. Settings, preferences, perspective, floating

- Canonical settings fields: `launchAtStartup`, `refreshIntervalMinutes`,
  `theme`, `quotaNotifications`, `providerPreferences`, `quotaPerspective`.
  Save is safe read-modify-write (`mergeSettingsWithRaw`): unknown future
  fields survive every save; canonical fields always win over stale raw
  values; corrupt storage preserves nothing. Whole-object erasure is gone.
- Provider preferences: canonical default order (registry append for new
  providers), hide/show, deduplication, removed-provider tolerance,
  at-least-one-visible refusal + all-hidden self-heal. Hidden affects
  presentation only — runtime, history, and notifications continue
  (guardrail-tested; attention rail consumes `visibleUsages`).
- Quota perspective: `Used | Remaining`, default `Used`, canonical metric
  `usedPercent`, Remaining = `100 - usedPercent` at presentation only;
  severity stays on usedPercent — 100% used renders as "Critical · 0%
  remaining" (visually verified in `dashboard-graphite-remaining.png`).
- Floating bar: Hide (temporary conceal) ≠ Off (`floatingBarEnabled=false`).
  `floatingBarEnabled`, `visible`, `x`, `y`, pin persist in
  `rate-limits.floating-quota.v1` with the same foreign-key passthrough
  semantics; dragging/hiding/pinning never erases `floatingBarEnabled`;
  re-enable restores prior geometry/pin. Verified by
  `floatingWindowPrefs` tests (40-test migration/floating suite) and
  harness flows 09/10/11.

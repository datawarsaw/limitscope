# v0.5 floating quota window prototype

Status: prototype on feature/v0.5-floating-quota-window. Not a release.
Base: 7411ea0c001633eafde0e89a0598914b719ff5a3 (v0.3.1, main).

## Purpose

A compact, always-available desktop bar for the production providers. It is a
separate Tauri window (floating-quota) so the main dashboard stays as it is.
The visual direction is the Rate Limits v0.5 concept mockup: a dark rounded
pill, provider identity, percentage, and a short meter. It is not a
pixel-perfect copy.

## Interaction model

- Default: icon, percentage, and a thin meter. No token counts or reset text.
- Hover: name, selected window, percentage, reset countdown, freshness.
- Click: a richer quick view (percentage, meter, reset line, source note,
  error text, and one Open action). Refresh, pin, and hide live only in the
  right-click menu.
- Right-click: Refresh, Open main window, Always on top, Hide floating bar.
- Drag the pill to move it. The last on-screen position is restored.
- Tray: Show floating quota bar. Showing it does not focus the main window.

The percentage is the highest usable quota window for that provider. Windows
are not averaged or summed. Mock providers are omitted. A provider with no
usable window stays visible as unavailable.

## Implemented

- Frameless, transparent, skip-taskbar window, always-on-top by default.
- Graphite, Glass, and OLED through the existing theme tokens.
- Healthy, stale, error (including last-good), and unavailable states.
- Stale stays marked even when a failed refresh is also showing.
- Position memory, dropped when it no longer overlaps a work area.
- Pin and hide, remembered locally.
- The bar and the dashboard each refresh on their own. The tray Refresh
  event, and Refresh from the bar, asks both to update.

## Deferred

- Auto-hide.
- Ultra-compact and vertical layouts.
- Click-through on the transparent margin.
- Opening a specific provider card inside the main window. Open focuses the
  existing dashboard, which already lists every card.
- Native desktop blur behind the window. Glass stays the in-app translucent
  card. A transparent shell can still flash or composite differently per
  WebView2 runtime.
- Popover flip is best-effort: the window grows downward, and moves up only
  when the current monitor's work area cannot fit it.

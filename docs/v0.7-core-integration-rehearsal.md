## 5. Explicit conflicts and combined contracts

### 5.1 `runtime.rs` — Codex attribution vs planType (provenance × identity-hardening)

- HEAD (identity-hardening) contract: success attribution carries the masked
  account (`build_codex_attribution` from `CodexAccount.account_hint`) so the
  last-good guard compares like-for-like with failure stamps.
- provenance-core contract: `plan_type` is projected onto the DTO only when the
  backend supplies it explicitly — trimmed, lowercased, empty → absent. Never
  inferred from model names.
- Combined: `normalize_codex` sets **both** — account attribution and explicit
  normalized `planType` are independent DTO fields. Strengthened by the existing
  `codex_surfaces_safe_plan_type` wire test (`"planType":"team"`, whitespace-only
  plan omitted from the wire).

### 5.2 `codex.rs` + `runtime.rs` — Codex account identity vocabulary (reset-credits × identity-hardening)

This was the central semantic collision. Both lanes evolved the same functions:

| Aspect | identity-hardening (v0.6 prereq) | codex-reset-credits (v0.7 lane) |
| --- | --- | --- |
| Mask | `account_hint`: last 8 chars of the account id, ≥16-char rule, alnum+dash | `mask_account_tail`: last 4 alnum chars, lowercased |
| Identity prefix | `chatgpt:{hint}` (matches what failure stamping emits) | `codex:{tail}` |
| Attribution struct | `CodexAccount { account_hint }` | redefined `CodexAccount { account_tail }` |
| Failure-path identity | `codex_identity` over the request-scoped account id | re-implemented over the local credential scope |
| Binding semantics | served/requested scope from `auth.json` | served account wins; credits bind only when observed identity is proven and does not contradict the stored scope |

- Combined contract adopted:
  1. **One identity vocabulary**: `account_hint` + `chatgpt:{hint}` everywhere —
     success attribution, failure stamps, last-good guard, and credit binding.
     The credits lane's `codex:{tail4}` was an artifact of being cut before the
     identity-hardening prereq existed; keeping it would have made the last-good
     guard compare success attributions against differently-formatted failure
     stamps and falsely drop retained data on every refresh.
  2. **Observed-wins attribution** (credits lane's improvement, kept): windows
     name the account the payload proves was served, falling back to the
     requested local scope.
  3. **Strict credit binding** (credits lane, kept verbatim, rekeyed onto
     `account_hint` via `bind_credit_account`): observed absent → credits
     unavailable; observed contradicts stored scope → unavailable; a mid-flight
     account swap can never attach one account's balance to another.
  4. **Freshness**: `trim_stale_reset_credits` drops credit observations older
     than `RESET_CREDITS_TTL_SECS` (900 s) from retained snapshots — a stale
     count can never read as a current balance, while quota windows are unaffected.
- Tests updated/strengthened: fixtures moved to realistic ≥16-char ids; new pin
  `credit_binding_uses_the_shared_account_hint_mask` (binding shares the
  attribution mask; raw id never on the wire); `normalize_codex_carries_account_bound_credits`
  now asserts `chatgpt:` identity; existing parity pins
  (`codex_and_zai_identity_formats_match_their_success_attribution`,
  `opencode_identity_formats_match_between_success_and_failure_paths`) all pass
  against the combined vocabulary.

## 7. Provenance-preserving contracts verified in the integrated tree

- Provenance core: manual bracket, BOUNDED ceiling (no EXACT production path —
  the run store rejects/persists EXACT never), cross-account UNAVAILABLE,
  reset-crossing incomparability, explicit `planType` only, no exact attribution,
  no prompt/response capture.
- Execution runs UX: one active run (conflict outcome, never overwrite), restart
  recovery via persisted active-run state, `EXECUTION_RUNS_MAX_RECENT = 20`,
  Finish bound to the original provider snapshot, declared harness labels only
  (no automatic process detection), forged EXACT rejected on load.
- Receipts: `EXECUTION_RECEIPT_SCHEMA_VERSION = 1`, deterministic byte-identical
  formatting (pinned by test), reset-crossing delta suppression (never emits the
  arithmetic delta across a reset), masked account only (secret-shaped input
  dropped), mandatory task-cost disclaimer, label-stable window sorting,
  deterministic file naming without account identifiers.
- Codex reset credits: `bankedCredits` / `currentlyApplicable` (absent = unknown,
  never zero) / `checkedAt` / `source`; 900 s freshness semantics mirrored in
  `src/lib/resetCredits.ts`; account binding per fetch; quota/credits independence
  (quota Live with credits unavailable is the normal projection);
  `bankedCredits` never interpreted as "resets available now" and never derived
  from windows/history.
- Usage analytics: 24h exact peak vs 7d lower-bound labeling, daily peak heatmap
  (absolute bands), reset-cycle annotation stable across ranges, explicit
  not-observed gap days (never zero-filled), estimated time-near-limit intervals
  (80/95 linear same-cycle interpolation), canonical `usedPercent` orientation,
  per-account isolation including unattributed history. Provenance runs are NOT
  fed into analytics (no accepted contract calls for it).

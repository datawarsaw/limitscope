## 4. Final product contracts

### Execution provenance and receipts

- Manual Start -> Finish only; no process attribution.
- Confidence remains `BOUNDED`; no exact task-cost claim.
- Account mismatch is `UNAVAILABLE`; reset crossing is incomparable with no
  fake delta.
- Every displayed delta includes: `Observed quota delta during execution (not exact task cost).`
- Receipts use versioned JSON and deterministic Markdown/file names, contain no
  raw provider snapshots, and expose only masked account data.

### Execution runs

One active run, restart recovery, recent completed runs, caller-declared
harness, original-provider finish binding, optional model/reasoning only when
explicitly supplied, account mismatch protection, reset-crossing handling, and
forged-EXACT rejection. The run affordance remains in the header on Overview
and Usage.

### Codex reset credits and identity

- `bankedCredits` is independent of `currentlyApplicable`; the observed
  `3 banked / 0 applicable` case renders exactly those two facts.
- Missing applicability is `UNKNOWN`, never zero.
- Credits never enter normal quota, history, predictions, or last-good cache.
- Credits bind only to canonical `chatgpt:<masked 8-char hint>` identity.

### Usage analytics and UI

- One analytics surface: summary, heatmap, reset-annotated trend, gaps, and
  estimated threshold timing.
- 24h detailed data is exact within retained detail; 7d compacted data is a
  lower bound where compaction applies.
- Heatmap peaks use daily `usedPercent` in fixed 0/25/50/75/100 absolute bands.
- Near-limit timing is estimated with piecewise-linear interpolation within a
  reset cycle. Gaps render as `Not observed`; charts are native SVG.

### Used / Remaining and invariant behavior

- Canonical metric: `usedPercent`.
- Used fill/text: `usedPercent`; Remaining fill/text: `100 - usedPercent`;
  values clamp to 0..100 and the physical axis remains left-to-right.
- Severity, thresholds, heatmap bands/colors, predictions, history, and
  notifications remain based on `usedPercent`.
- Progressbar `aria-valuenow` and text match the visible perspective and name
  `used` or `remaining`; severity remains separately available as text.
- Floating `Hide` and `Off` remain distinct. Fill represents consumed quota in
  Used mode and available quota in Remaining mode.

### Settings, Local Data, history, and providers

- Settings contain exactly `launchAtStartup`, `refreshIntervalMinutes`,
  `theme`, `quotaNotifications`, `providerPreferences`, and `quotaPerspective`.
  Unknown fields survive saves, preference changes, and Reset Preferences.
- History clear clears history only. Provider cache clear removes persisted
  recovery data while the current runtime snapshot remains visible. Execution
  clear removes active/completed execution data and requires explicit active
  run confirmation. Preferences reset restores defaults, returns perspective
  to Used, and preserves history and unrelated durable data.
- `.limitscope-provenance-run.json` remains outside the desktop clear surface.
  There is no arbitrary path-delete IPC or provider credential mutation.
- Production provider correctness remains `openai-codex`, `zai`,
  `opencode-go`, `antigravity`, and `grok`, with no browser-cookie scraping or
  cross-account retained last-good state.
- History retention, account isolation, live-only history eligibility, and
  80/95 crossing-only notification behavior remain unchanged.
